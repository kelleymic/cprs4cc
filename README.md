# CPRS4CC — External Record Viewer

A single-page medical record viewer laid out like VistA CPRS. It imports outside records from many sources, restructures every item into **HL7 FHIR R4** (US Core-aligned) with a reference to the source file and page, and exports the result as a FHIR Bundle.

All sample data in this repository is synthetic or fictional. There is no real patient information.

## Quick start

Open `index.html` in a browser. It is self-contained apart from two libraries loaded from cdnjs (pdf.js 3.11.174 and JSZip 3.10.1). To load the bundled samples with **File › Load Sample Records**, serve the folder over HTTP so the page can read `samples/`:

```
python3 -m http.server 8000
# then open http://localhost:8000/index.html
```

## What it does

| Area | Summary |
|---|---|
| Viewer | CPRS-style tabs: Cover Sheet, Problems, Meds, Notes, Consults, D/C Summ, Labs, Reports, and Ext Data for content that could not be mapped. Patient banner, Postings, detailed display of every item with its source references. |
| Import | FHIR R4 (JSON, Bundle, NDJSON), HL7 C-CDA R2.1, HL7 v2 ORU, PDF printouts with a text layer, plain-text reports (VA Blue Button), HTML exports, and ZIP files of any of these. |
| Structure | Each vital sign, lab result, problem, medication, allergy, immunization, procedure, visit and document is its own FHIR resource. Lab results carry date/time, value, units, low and high limits, abnormal flag, specimen, performing lab and comments. |
| Source references | Every item records file name, page(s) and location (line, HL7 segment, CDA section/entry or Bundle entry), plus the extraction method. Identical items found in several files are merged and keep all their sources. |
| LOINC | 207 common lab results mapped by printed name and specimen, including serum tumor markers (`src/catalog.txt`). |
| Graphs | Click a lab or vital value to graph all values of that item, with adjustable time period and the normal range as dotted red lines. |
| Export | FHIR R4 Bundle (with a Provenance per source file and its SHA-256 hash) or a flat CSV. |
| PDF extraction with Claude | Optional. Identifiers, including every date, are replaced with placeholders in the browser, the user reviews the exact text, Claude returns structured items, each value is verified against its cited line, and the original values are restored locally. Extraction without substitution is offered only for an organization endpoint marked as approved for patient information. |

See [`docs/DESIGN.md`](docs/DESIGN.md) for the design decisions, formats and known limits.

## Privacy and compliance

- By default nothing leaves the browser.
- Claude extraction is opt-in. Inside claude.ai it uses the viewer's own Claude account, which is not covered by a HIPAA business associate agreement, so identifiers are always removed first and the user reviews the text before sending.
- An organization endpoint (for example inside the VA network or covered by a BAA) can be configured in **Tools › Claude Extraction Settings**. That requires hosting `index.html` on the organization's network.
- Automated de-identification can miss identifiers in narrative text. Whether de-identified text meets HIPAA or VA requirements is a decision for the facility Privacy Officer and ISSO.
- This software is not a certified medical device and is not connected to VistA.

## Repository layout

```
index.html          built viewer (generated by build.py; also what is published)
build.py            inlines src/engine.js + src/catalog.txt into src/ui.html -> index.html
src/ui.html         CPRS-style interface
src/engine.js       importers, normalization to FHIR, de-identification, Claude extraction, export
src/catalog.txt     LOINC mapping table (code | long name | printed names | specimen)
samples/            synthetic and fictional test records (see samples/README.md;
                    the HL7 C-CDA examples are linked there, not included)
tests/              Node test scripts (no browser needed)
tools/              scripts that generate the fictional sample PDFs and text files
docs/DESIGN.md      design notes
```

## Build and test

```
npm install                 # pdfjs-dist, @xmldom/xmldom, jszip (test-only dependencies)
python3 build.py            # regenerate index.html after editing src/
cd tests
node test.js                # import every sample, print counts and patient identity
node catcheck.js            # validate LOINC check digits in src/catalog.txt
node maptest.js             # printed name + specimen -> LOINC
node idtest.js              # patient name/DOB detection
node rtest.js               # reference-range parsing
node deidtest.js VA_ROI_Printout_HESSEL_2026.pdf   # de-identification leak check
node ingesttest.js          # Claude extraction with a mock reply (verification, restoration)
node pathtest.js            # fallback to rules, direct (no substitution) mode
```

`tests/mockgw.py` is a stand-in for an organization's Claude endpoint (Messages API format) used for browser testing.
